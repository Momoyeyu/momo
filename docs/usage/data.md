# 备份与迁移

配置、对话、记忆、存档、参考音和自行导入的形象都属于你的本地数据。升级前建议先导出备份；不要直接复制仍在运行的 SQLite 文件，以免遗漏 WAL 中的新记录。

使用应用内的数据导出 / 导入入口，将后端一致性备份和浏览器 IndexedDB 中的模型 ZIP 一同放入带版本、文件清单与校验值的归档。导入前校验内容与路径，应用失败时恢复原现场。旧 Rust 版本的数据不自动当作新格式读取。

备份可能包含对话服务密钥和私人内容，只应保存在自己控制的位置，不上传到 issue、公共仓库或公开测试报告。应用日志和安装资源包不是用户数据备份。

正式桌面应用使用独立 v2 数据目录；浏览器开发版和测试版应使用自己的数据目录，不覆盖现有体验档。卸载程序与主动删除用户数据是不同操作，迁移前先保留可恢复副本。

## 从 momo-web 迁入

旧版 momo-web 没有新的整包导出入口。先停止旧后端并复制它的完整用户数据目录（包含配置、参考音和 SQLite / WAL）；保留原目录作为回退。使用新仓库的浏览器开发模式，以复制目录作为 MOMO_DATA_DIR 启动后端，并在原来的浏览器来源（包括端口）打开新前端。这样导出入口才能同时读取复制的后端数据和该来源 IndexedDB 中的形象。

在设置中导出归档，退出临时开发服务，然后在桌面版导入。两边都先保留备份；确认对话、记忆、形象、参考音和存档完整后再处理旧目录。不要同时用两个后端写同一个数据目录，也不要把原目录直接交给迁移测试。
